## Native foundation follow-up — 2026-11-16

- Added an opt-in Tauri WebDriver build using the official WebdriverIO Tauri service. It builds the real app and calls native vault IPC through the WebView; it does not mock commands. The test build has a separate app identifier, requires an explicit temporary data directory, and rejects a missing or mismatched test configuration before opening `VaultSession`.
- The WebDriver server is test-only, unauthenticated, and binds to loopback. It can control the test app for any local process that can reach that port, so tests use synthetic data only. The `e2e` feature is debug-only; it compiles no macOS Keychain provider calls. The regular app build and default frontend build do not include the WebDriver bridge. E2E builds use `src-tauri/target/native-e2e`, separate from the normal debug binary.
- Native E2E frontend assets are built into the ignored `dist-native-e2e` directory, and the E2E Tauri config points there. This keeps test bridge assets out of the normal `dist` output even when an E2E build runs last.
- Actual compiled macOS app runs passed: create vault, edit and persist a synthetic transaction note, save and lock, reject a concurrent process specifically on the vault lock, restart, reject a wrong passphrase without unlocking, reopen with the correct passphrase, and verify the changed note. A deliberate corruption of the current synthetic snapshot then exercised wrong-passphrase rejection and correct previous-snapshot recovery, restoring the changed note. Data was isolated under `/private/tmp/geldapp-e2e-foundation-*`.
- CI is configured to run these setup, competing-process, restart, and recovery cases on macOS and Windows. Hosted CI has not yet run on this candidate; local macOS runtime smoke passed.
- Each native CI job uploads its WDIO logs and isolated synthetic vault directory even when a test fails; artifacts are retained for 14 days. The vault data contains test-only synthetic records.
- `npm audit --omit=dev` reports zero vulnerabilities. Full audit has 19 moderate package entries, no high or critical findings; `npm audit --audit-level=high` is now a CI gate. Entries are `@wdio/cli`, `@wdio/globals`, `@wdio/local-runner`, `@wdio/mocha-framework`, `@wdio/native-core`, `@wdio/native-types`, `@wdio/native-utils`, `@wdio/runner`, `@wdio/session`, `@wdio/snapshot`, `@wdio/tauri-plugin`, `@wdio/tauri-service`, `archiver`, `expect-webdriverio`, `glob`, `minimatch`, `mocha`, `readdir-glob`, and `webdriverio`. They trace to two moderate advisories: [GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) affects `glob` through 14.0.1 (fix 14.0.2+) and can bypass AbortSignal cancellation, allowing traversal to continue after timeout; [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) affects `minimatch` before 11.0.1 and allows globparts amplification denial of service. Vulnerable installed nodes are test tooling only (not production). `npm audit fix --dry-run` reports fixing them through a breaking downgrade to WDIO 9.33.1; the real-app-tested WDIO 10/Tauri service stack is retained without broad overrides.
- Signed Keychain behavior, actual biometric prompt, cancellation/unavailable/enrollment-change behavior, and physical Touch ID remain unverified. These E2E tests deliberately disable every Keychain provider entry point and do not turn on biometric unlocking.
